# 第一阶段需求

## 建设目标

使用现有 OpenAI 兼容 API Key 建设公司内部统一 AI 服务。业务系统只调用中台业务接口，不接触真实上游 Key。

## 功能范围

### 基础调用层

- 非流式 Chat Completions。
- 流式调用基础能力。
- 连接、读取和流空闲超时。
- 错误分类和最多两次有限重试。
- Token 用量汇总。
- 业务请求与上游调用审计。
- OpenAI 兼容文字转语音调用。

### AI 能力层

- 信息提取。
- 评价分析。
- 内容生成。
- 结构化 JSON 输出与校验。
- 文字转语音合成。

### 招聘场景

- 简历文本解析。
- PDF/DOCX 简历临时解析，不保存文件或业务结果。
- 岗位匹配与初筛。
- 面试题生成。

### 文字转语音场景

- `tts-1` 与 `tts-1-hd` 独立语音模型配置。
- 多声音、语速和 MP3/WAV 输出。
- 浏览器试听与音频下载。
- 用户可自行选择完整音频或流式 MP3 播放。
- 语速滑块立即影响当前试听；重新生成后所选语速写入可下载音频。
- 流式模式支持最多 50000 字符，并按中英文自然句界拆分单次上游请求。
- 浏览器不支持 MP3 渐进播放时自动回退为完整音频播放。
- 输入文本和生成音频不持久化。

## 非功能要求

- 不泄漏上游 API Key。
- 默认不保存完整简历和提示词。
- 每个错误返回稳定错误码和 requestId。
- 本地可在 mock 模式下独立运行。
- 模块可测试，前后端可以分别构建。
