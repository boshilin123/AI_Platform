# TTS 语速交互修复总结

## 讨论主题

用户在右侧音频已经生成后拖动左侧语速滑块，播放器速度没有变化，容易判断为语速功能失效。

## 关键结论

- 后端和上游语速参数均有效，问题属于交互语义缺陷。
- 原实现中的语速仅用于下一次合成，不会修改已经生成的音频。
- 语速需要区分“当前试听速度”和“下载音频中已经写入的合成语速”。

## 实测

使用同一条虚构英文短文本直接调用真实上游：

| 合成语速 | 音频时长 |
| ---: | ---: |
| 0.5× | 7.296 秒 |
| 2.3× | 1.440 秒 |

结果证明上游 `speed` 参数有效，临时测试音频已删除。

## 完成修改

- 拖动语速滑块会立即调整右侧现有音频的浏览器试听倍速。
- 新生成音频仍将所选语速提交给上游，下载文件保留该合成语速。
- 当前试听速度与已生成音频不同时，页面提示需要重新生成才能更新下载文件。
- 结果区新增“合成语速”，生成按钮在语速变化后显示“重新生成语音”。
- TTS 二进制与流式接口新增 `X-Audio-Speed`，前端按响应头记录实际提交语速。
- 新增上游请求体语速断言和接口响应头断言。
