# TTS 流式播放与中英文长文本改造总结

## 讨论主题

在保留现有完整音频合成模式的前提下，为文字转语音助手增加用户可选的流式播放，并解决
OpenAI 兼容 Speech API 单次 4096 字符限制及中英文长文本播放问题。

## 关键结论

- 流式播放是原始 MP3 音频字节流，不是 SSE。
- 非流式接口保持 4096 字符和 MP3/WAV，避免破坏既有调用方。
- 流式接口最多接收 50000 字符，单个上游请求仍不超过 4096 字符。
- 中文优先按 `。！？；`，英文优先按 `.?!;`，再按换行、逗号、冒号和单词空格切分。
- 语言由语音模型根据原文自动识别，服务不翻译文本；所有分段使用相同声音和语速连续播放。
- 第一段尚未输出时可有限重试；任何音频发出后，后续错误终止流且不透明重试。
- 一次长文本任务只写一条业务审计，每个真实分段调用和首段重试分别记录上游明细。

## 完成修改

- `infrastructure/speech` 新增可关闭的异步音频流响应，使用 HTTPX 流式读取、类型与大小校验。
- `capabilities/speech_synthesis` 新增流式执行与完成、失败、断连审计。
- `scenarios/tts/text_segmenter.py` 新增独立中英文文本分段器。
- 新增 `POST /api/v1/tts/synthesize-stream`，返回分块 MP3 和分段数量响应头。
- 前端新增“流式播放”开关；开启后固定 MP3，支持时通过 MediaSource 边收边播。
- 浏览器不支持 MP3 MediaSource 时自动回退为完整 Blob 播放。
- 流式完成后仍可下载完整 MP3；清空页面或离开页面会取消当前传输。
- 新增流式总字符上限配置和部署环境变量，并更新接口、架构、需求和部署文档。

## 错误与修正

- 首轮容器测试继承了 Compose 的生产鉴权配置，导致多项接口返回 401；改用隔离 SQLite、
  Mock AI、空内部令牌和测试管理员配置后恢复正常。
- 英文分段器首次遗漏英文句号，导致首段跨过自然句界；加入 `.` 后单元测试通过。
- 流式分段会去除边界空白，但审计改为使用原始输入计算哈希和字符数，避免审计失真。
